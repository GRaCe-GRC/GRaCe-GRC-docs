# Glossary

| Term | Meaning |
|---|---|
| Control | A safeguard or practice that addresses a requirement, such as a privileged access review. |
| Control mapping | A link between a regulatory requirement and the control that satisfies it, with a rationale and review status. |
| Control configuration | How a control is tested in Project 2: test procedure, evidence requirements, pass criteria and connectors. |
| Connector | An integration that retrieves evidence from a source system such as GitHub, Splunk, Datadog or AWS. |
| Evidence | An artifact that shows whether a control operates, stored in S3 with a SHA-256 hash. |
| Finding | A compliant or non-compliant result imported into Project 3 for scoring. |
| Remediation | Work to fix a non-compliant finding; verified by re-assessment in Project 2 (closed-loop verification). |
| OSCAL | NIST's Open Security Controls Assessment Language: machine-readable formats for catalogs, assessment results and POA&M. |
| POA&M | Plan of Action and Milestones: the list of open weaknesses and how and when they will be fixed. |
| RAG | Retrieval-augmented generation: giving an LLM relevant retrieved text before it drafts an answer. |
| REF | An identifier of an entity owned by another project, read through that project's internal service API. |
| SNS / SQS | Amazon Simple Notification Service (topics) and Simple Queue Service (queues), used for events between services. |
